ShareSafe System Architecture and Security Engineering

An in-depth technical analysis of ShareSafe’s decoupled frontend interface, serverless-ready Flask backend, local dual-engine document pipeline, and on-device Intelligent Privacy Assistant engine.

SECTION A

System Overview & Topography

ShareSafe is built upon a privacy-first, decoupled micro-architecture designed for high performance, deterministic execution, and zero persistent data leakage. Unlike conventional SaaS redaction utilities that transmit documents to remote cloud compute clusters, ShareSafe performs all file parsing, OCR rendering, regex entity detection, risk scoring, and raster burn-in either directly on the user's local operating system or inside an ephemeral serverless container.

Client Layer (Frontend)

Jinja2 server-rendered templates with reactive vanilla JavaScript controllers (canvas_editor.js, app.js), HTML5 Canvas overlay, synchronized Before/After split comparison, and responsive CSS.

Application Layer (Backend)

Flask (Python 3.13) RESTful microservice managing session isolation, magic-byte header validation, dual-mode text extraction, algorithmic checksum verification, and export generation.

Processing & Intelligence Core

Modular Python engine: PyMuPDF for native vector parsing, OpenCV for QR computer vision decoding, Windows/Tesseract OCR, and the local rule-based PrivacyAssistant.

SECTION C

Frontend and Backend Architecture

Frontend Architecture

ShareSafe employs an ultra-fast, zero-framework vanilla JavaScript client architecture optimized for low memory overhead and maximum rendering precision:

  • Jinja2 Server Rendering: base.html establishes a shared structural shell with sticky navigation and accessible modal dialogs; index.html delivers the upload dropzone; workbench.html houses the multi-pane studio.
  • Dual-Layer Canvas Controller (canvas_editor.js): Implements an HTML5 canvas overlay on top of high-resolution document previews, mapping document native coordinates to scaled DOM coordinates.
  • Synchronized Before/After Comparison: A high-performance clip-path divider slider synchronizes original and sanitized image layers with zero repaint lag.
  • Interactive Selection Sync: Checkboxes, canvas bounding boxes, assistant cards, and toolbar style controls synchronize state reactively via a client-side selectedIds Set.
Backend Architecture

The server-side component is built as a modular Python 3.13 Flask application with clear separation of concerns across the core/ package:

  • Modular Domain Design: Separate dedicated modules for detection (regex_detector.py), computer vision (qr_detector.py), OCR abstraction (ocr_engine.py), risk calculation (risk_assessor.py), assistant guidance (privacy_assistant.py), and file sanitization (redactor.py).
  • Stateless Ephemeral Session Manager: Uses UUIDv4 session identifiers. Sessions are isolated in transient file system sandboxes (uploads/<session_id>) with automatic purge endpoints.
  • Zero-Roundtrip Base64 Payloads: In serverless deployments (such as Vercel), preview images and sanitized outputs are delivered via embedded Base64 data URIs to guarantee zero broken image links.
SECTION D

The Document Processing Pipeline

The document processing lifecycle proceeds through six sequentially guarded stages:

Stage 1
Header Validation & Rendering

Magic byte verification; multi-page PDF rendering at 150 DPI into PNG preview frames; page dimension extraction.

Stage 2
Glyph & Text Stream Extraction

PyMuPDF native character extraction with exact bounding boxes; fallback OCR for image-only scans via Windows/Tesseract.

Stage 3
Entity Detection & Algorithmic Filtering

Contextual regex scanning, Verhoeff checksum calculation for Aadhaar, ITD validation for PAN, Luhn for cards, false-positive suppression.

Stage 4
Computer Vision QR Forensics

OpenCV image scanning, payload decoding, semantic parsing of payment URIs, Wi-Fi parameters, and URLs.

Stage 5
Assistant Analysis & Scoring

Composite risk score calculation; PrivacyAssistant generates explainable recommendations and narrative summaries.

Stage 6
Irreversible Burn-in & Export

Raster pixel overwrite, vector text stream clipping, EXIF/PDF metadata eradication, and cryptographic SHA-256 certificate generation.

SECTION E

The AI Assistance Architecture (Local Expert Engine)

A critical architectural requirement of ShareSafe is that the AI Assistance feature operates under strict privacy sovereignty. The current implementation in core/privacy_assistant.py is a specialized, local deterministic expert reasoning engine:

Engine Model & Execution Environment

Implemented entirely in native Python as an algorithmic expert system. It does not invoke external third-party cloud APIs (such as OpenAI, Anthropic, or Google Gemini), avoiding external network latency, recurring API costs, and third-party data disclosure risks.

Inputs Accepted & Preprocessing

Receives structured findings from the scanner pipeline: entity type (e.g. aadhaar, pan, phone, qr_code), confidence level, statutory checksum status, bounding boxes, masked text previews, and the active sharing context.

Rule Evaluation & Recommendation Logic

Evaluates findings against a weighted decision matrix. Formulates three priority tiers: HIGH_PRIORITY (statutory records, payment credentials), REVIEW (uncertain OCR matches, contact details in private contexts), and INFORMATIONAL (standard URLs, harmless codes).

Credential & Data Protection

Because no external AI services are invoked, zero API keys are stored, handled, or exposed. Document data remains strictly within host memory, ensuring zero cloud telemetry and zero third-party model training on user data.

Error Handling & Privacy Safeguards in AI Guidance

  • Statutory Verification Decoupling: When an OCR scan detects a numeric sequence resembling a government ID but fails the Verhoeff checksum, the assistant downgrades priority to Review Recommended and alerts the user of potential OCR variance.
  • Safe Payload Discrimination: Standard public web links inside QR codes are explicitly designated as INFORMATIONAL, preventing automated false alarms on corporate marketing links.
  • Non-Destructive Staging: Accepting an assistant suggestion simply toggles the finding's checkbox for preview sanitization. Original files are never modified without explicit user download export.

SECTION G

Security & Privacy Engineering Safeguards

File Validation & Buffer Safety

Raw magic-byte header inspection prevents extension spoofing. File processing is constrained by a 50-page ceiling and 32 MB size thresholds to prevent decompression bombs.

Ephemeral RAM Sandboxing

Uploaded documents reside in transient, isolated session folders. A dedicated purge endpoint and background cleanup daemon securely purge expired artifacts.

Zero Cloud Telemetry

No user files, extracted text, or detected credentials are ever logged, cached remotely, or transmitted across external networks. All computations run in-memory.

Irreversible Burn-in

Redactions overwrite underlying raster pixels and purge PDF font glyph streams, preventing forensic copy-paste recovery or reverse-engineering.
